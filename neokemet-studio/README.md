# NeoKemetAI Animation Studio

A local, standalone generator for 2D animated documentary shorts about ancient Egypt, in a
vintage travel-poster print style. You write (or import) a script, arrange the scenes in a
storyboard, add narration, and export an MP4 — all on your own PC.

- Runs on Windows (also macOS / Linux). No Claude, no cloud rendering, no paid service needed.
- Engine: Remotion + React + TypeScript + SVG. FFmpeg is bundled with Remotion; nothing extra to install.
- Offline narration with Piper. Optional local script/storyboard generation with Ollama.
- Output: 9:16 (1080×1920), 16:9 (1920×1080) or 1:1 (1080×1080), 24–60 fps. Short films or long documentaries: up to 40 scenes of any length.

## Install (Windows)

1. Install **Node.js LTS** (version 18 or newer) from https://nodejs.org.
2. Double-click **`Start-NeoKemetAI-Studio.bat`**.
   The first run installs the studio (internet needed once, a few minutes) and then opens
   http://127.0.0.1:4173 in your browser. Keep the black window open while you work.
3. The first preview or export also downloads a small headless Chrome that Remotion uses to
   draw frames (once, about 100 MB). After that the studio works offline.

Optional, for offline narration — run once in PowerShell from this folder:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup-piper.ps1
```

It downloads Piper and the British English voice `en_GB-alan-medium` into `tools\`. Another
voice: add `-Voice en_US-ryan-high` (any name from the Piper voice list).

On macOS / Linux, start the studio with:

```bash
npm install
```

```bash
npm start
```

## Make a video

The app has five numbered tabs; work left to right.

1. **Project** — title, topic, output format, frame rate, subtitles on/off. The film length is shown here.
2. **Script** — type, paste or import a `.txt` / `.md` script. **Each paragraph is exactly one scene**:
   separate scenes with a blank line. A paragraph is never split, however long, and its full text
   is the narration. Up to 40 paragraphs. Then either
   - **Build storyboard from script** — offline keyword rules choose a template, environment and
     characters for each paragraph; or
   - **Generate storyboard with Ollama** — optional, uses a model running on your PC.
3. **Storyboard** — one card per scene. Choose the visual template, environment, camera move,
   characters and their actions, on-screen label, and edit the narration. *Preview frame* draws a
   still; *Render this scene* exports just that scene. Reorder, duplicate or delete scenes.
4. **Narration & sound** — *Generate narration offline (Piper)* speaks every scene, or import your
   own recording per scene in the storyboard. Choose the built-in score, your own music file, or
   none; switch the generated sound effects on or off; set volumes.
5. **Export** — *Export full MP4*. Progress is shown per scene; the file appears in
   `workspace\output\` with a player and a download link.

**Building a storyboard is safe.** The new storyboard is validated as a whole before it replaces
the old one. If anything is wrong (for example more than 40 paragraphs) you get a message and
the current project stays exactly as it was.

**Timing is automatic.** Scene lengths vary freely — a 36-paragraph script makes a 13–15 minute
film with scenes of 15–30 seconds each. Each scene lasts as long as its narration (half a second of lead,
the measured speech, a short tail), and subtitles are spread across the spoken span. Set
"Length" on a scene only if you want to override that.

**Re-exports are fast.** Every scene is rendered to its own cached clip. Changing one scene
re-renders only that scene; changing music, volumes or narration audio re-renders nothing.

## Visual library

All artwork is hand-built SVG generated by code (no image files except three procedural paper
textures). Everything is seeded, so the same project always renders the same frames.

- **Documentary templates** — Royal Pharaohs, Tomb Robbery, Priests Rewrapping (see below).
- **Templates** — title card, landscape, characters, procession, artifact, tomb interior
  (intact / looted), tomb cutaway, coffin chamber, journey map, end card.
- **Royal Cache presets** — the 18 hand-directed shots of the original film, usable as scenes
  in any project. They take no options and stretch to the narration length. They were composed
  for 9:16; in 16:9 the sides of some presets show plain paper.
- **Environments** — Theban cliffs, Deir el-Bahari, Giza pyramids, Nile valley, temple
  courtyard, village, open desert, market street, painted tomb wall.
- **Characters** — priest, pharaoh, noblewoman, scribe, bearer, villager, 19th-century worker
  and two officials; actions: stand, walk, talk, read a papyrus, carry a torch, hold a staff, point.
- **Objects** — royal coffin, papyrus scroll, canopic jars, amulets, seated statue, obelisk,
  treasure chest; plus biers, boats, stalls, columns, palms, houses.
- **Cameras** — push in, pull back, pan left / right, rise, static, all with multiplane parallax.

## Documentary templates (phase 1)

Three templates built for documentary storytelling. Unlike the generic templates, each has
its own parameters, shown as extra fields on the scene card and saved in the scene's `params`.
*Label* and *Subtitle* are the scene's on-screen caption.

| Template | Shows | Parameters |
|---|---|---|
| **Royal Pharaohs** | A king enthroned between fan bearers, standing with attendants, or as a colossal statue; the chosen name appears on a cartouche plate | Pharaoh (Ramesses II, Seti I, Thutmose III, Amenhotep I, Seqenenre Tao, Generic Pharaoh) · Pose (seated, standing, statue close-up) · Environment (temple courtyard with columns, theban limestone cliffs, royal burial chamber, desert plateau) · Camera (slow push in, pan left, pan right, rise) |
| **Tomb Robbery** | A burial in its original order that is then opened, looted or damaged during the scene — schematic, nothing graphic | Stage (intact, opened, looted, damaged) · Environment (royal burial chamber, hidden cliff tomb, corridor with side chamber) · Camera (slow push in, pan right, pan left) · Show torch · Show scattered objects |
| **Priests Rewrapping** | Two to four priests and workers in linen at a coffin, a wrapping table, a labelling bench, or carrying a bier | Action (inspect coffin, rewrap mummy, record labels, carry remains) · Environment (work chamber, temple chamber, burial preparation room) · Camera (slow push in, pan left, pan right) |

**In the Storyboard:** pick the template under *Documentary* in the Template list. Its fields
appear on the card straight away with sensible defaults; change any of them, then use
*Preview frame* or *Render this scene*. Parameters are optional in the project file — a scene
without `params` uses the defaults, so older projects are unaffected.

**From a production `.md` script:** the importer reads each scene's *Visual* direction, its
title and its narration and scores them against cue words. Directions count double. When the
score is high enough it selects the template and fills in the parameters (narration on its
own must contain two strong cues, so a passing mention of "pharaohs" changes nothing):

- *Royal Pharaohs* — Ramesses, Seti, Thutmose, Amenhotep, Seqenenre, colossal statue, royal /
  famous rulers, pharaoh; "temple" alone is only a weak hint.
- *Tomb Robbery* — looted, robbery, thieves, damaged coffin, disturbed tomb / mummies, gold
  vanished, burial threatened.
- *Priests Rewrapping* — priests of Amun, rewrapped, repairing burials, fresh linen, labels
  recorded, dockets, transfer.

Details such as "colossal statue", "by torchlight", "corridor", "pan left" or "linen labels"
set the pose, torch, environment, camera and action. Scenes that do not match keep the
importer's previous choice, and a direction that explicitly asks for a cutaway, a map or rows
of coffins is never overridden. The first and last scenes stay title and end card. Every
choice is only a starting point: review it in the Storyboard.

`projects/demo-template-library` has one example scene of each template.

The pharaoh name changes the name plate and trim colour, not a likeness: figures have no
faces by design.

## Phase 2: Reuse original Royal Cache animations

Eight existing hand-directed shots are now **editable, reusable presets** in the
Storyboard, without redrawing the artwork or changing their original files:

| Preset | Original shot |
|---|---|
| `rc-07` | Deir el-Bahari / Hatshepsut temple |
| `rc-08` | TT320 shaft and passages cutaway |
| `rc-11` | Nineteenth-century Theban family and village |
| `rc-12` | Goat story at the tomb opening |
| `rc-14` | Antiquities market and clues |
| `rc-15` | Historical discovery of 1881 |
| `rc-16` | Removing and hoisting royal coffins |
| `rc-17` | Pharaohs' Golden Parade, 2021 |

On these scenes the **Framing** (original / close-up / wide), **Camera adjustment**
(original / push in / pull back / pan left / pan right), **Portion of original
animation** (full / opening half / closing half), **Colour grade** (original /
warm dusk / cool night), and **Display extra scene label** controls appear
automatically. With no `params` or all controls left at default, the **original
shot renders unchanged**. Custom caption text is only displayed if the extra
label switch is enabled. These adjustments transform an existing shot; they
do not rearrange its actors or re-choreograph its action. Some shots have
original fixed captions which remain visible.

**Production-script Markdown:** the importer now recognizes strong, distinctive
*Visual* directions for these eight shots and uses the existing artwork.
It does **not** select these presets from the narration alone. Ambiguous
directions retain the existing matching behavior, and the first and last
scenes remain title and end card. Review all choices in Storyboard.

**No script edits required:** `Royal_Cache_Long_Production_Script.md` is
unchanged. Re-importing replaces the current scene list; create a new test
project to test automatic mapping without overwriting hand-edited scenes,
saved audio, or your current 36-scene storyboard.

Run `npm run typecheck` and `npm test`, then preview and render a sample
scene from each reused preset in 16:9 before using the entire film.

## Optional local AI (Ollama)

Install Ollama from https://ollama.com, pull a model, and the status pill in the header turns green:

```bash
ollama pull llama3.1
```

Set the model name in **Settings**. The studio sends the model a JSON schema of the scene
format and validates the answer; an invalid answer is sent back once for correction and
otherwise rejected with the reason. AI-written narration is not fact-checked — read it before
you export. Everything else works without Ollama.

## Optional paid service (ElevenLabs)

Off by default and never required. If you enable it in **Settings**, narration text is sent
to ElevenLabs and billed to your account, and the app asks for confirmation each time. The
key is kept only in `workspace/settings.json` on your PC (not committed), or read from the
`ELEVENLABS_API_KEY` environment variable.

## Project files

A project is a folder with a `project.json` (validated against `shared/schema.ts`) and its
audio:

```json
{
  "title": "The Great Pyramid",
  "format": "9:16",
  "fps": 30,
  "scenes": [
    {
      "id": "s02",
      "template": "characters",
      "environment": "temple-courtyard",
      "camera": "pan-right",
      "label": "King Khufu",
      "cast": [{ "kind": "scribe", "action": "read" }, { "kind": "pharaoh", "action": "talk" }],
      "narration": "It was built for King Khufu of the Fourth Dynasty…",
      "narrationFile": "narration/02-s02.wav"
    }
  ]
}
```

## Adding to the library

- New environment: add an id to `ENVIRONMENTS` in `shared/catalog.ts` and a `case` in
  `engine/src/components/Environments.tsx`.
- New character: add an id to `CHARACTERS` and its costume in `engine/src/components/Figures.tsx`.
- New template: write a component in `engine/src/templates/`, register it in
  `templates/index.tsx`, and describe which fields it uses in `TEMPLATES`. It appears in the
  storyboard selector and in the Ollama schema automatically.

## Troubleshooting

- **"Port 4173 is already in use"** — the studio is already open in another window; close it, or set `PORT` to another number.
- **"Piper is not installed"** — run `scripts\setup-piper.ps1`, or import your own narration audio per scene.
- **Ollama pill is grey** — Ollama is not running; it is optional.
- **First export is slow to start** — the engine is being bundled and headless Chrome downloaded; this happens once.
- **Export fails on one scene** — the message names the scene; use *Render this scene* to reproduce it.

## Import a structured production script (.md)

Open **3 · Storyboard** and choose **Import Production Script (.md)**. Select a Markdown file with numbered scene headings such as `**Scene 01 — A sound beneath the sand**`, followed by `**Voiceover**`, `**Visual:**`, and `**Sound / transition:**`. Optional `### Chapter: ...` headers are retained as editorial metadata.

The importer shows a **read-only preview** and validates the complete candidate (up to 40 scenes). Press **Apply validated scenes** to load it into the open project, review the results, then press **Save project**. Validation errors do not change the existing storyboard. Importing does **not** call ElevenLabs, modify audio files, or render video.

Every scene receives its complete voiceover as the narration text. Production notes are shown in expandable **Production notes** sections for editing. Basic template, camera, ambience and environment selections are inferred from the **Visual** directions; unique choreography, bespoke assets, transitions and custom sound cues remain editorial instructions and must be implemented manually where unsupported. Scene duration follows its spoken audio when available, otherwise the existing text estimator is used.

For a long documentary such as the 36-scene Royal Cache production file, use **16:9** when prompted. Keep the original production Markdown available because scene descriptions are not substitutes for custom direction. The feature branch can be tested locally with `npm test`, `npm run typecheck`, and the existing Windows launcher.
